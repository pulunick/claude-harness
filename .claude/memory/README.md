# .claude/memory — 두 사람이 공유하는 Claude 메모리

Claude Code는 세션마다 `~/.claude/projects/<경로인코딩>/memory/`를 자동 로드한다. 기본값은 **각자 PC 로컬**이라 한 사람의 Claude가 배운 것이 상대에게 안 간다. 그래서 그 폴더를 이 디렉터리로 링크한다(`setup/common/link_memory.py` — 맥 심링크 / 윈도우 정션). 링크가 되면 **Claude가 메모리를 쓰는 순간 그것이 커밋 대상**이 되고, `/wrap`으로 밀면 상대가 다음 `/start`에서 받는다.

> 경로인코딩 = 저장소 절대경로의 영숫자 아닌 문자를 전부 `-`로. 세션은 **저장소 루트에서** 연다 — 하위 폴더에서 열면 다른 인코딩 폴더를 보고, 거기 쓴 메모리는 고립된다.

## 공유 / 개인 구분 — 접두사로

| 접두 | 성격 | git |
|---|---|---|
| `feedback_` | 작업 방식에 대한 지시·교정 ("이렇게 해줘") | **추적** |
| `project_` | 프로젝트 사정·방향·제약 (코드·git에서 못 읽는 것) | **추적** |
| `reference_` | 외부 링크·도구·계정 포인터 | **추적** |
| `local_` | 그 사람 PC 사정·개인 취향 | **gitignore** |

## 작성 규약

파일 하나에 사실 하나. 프론트매터:

```markdown
---
name: <kebab-case-slug — 파일명과 같게>
description: <한 줄 요약 — 회상 시 관련성 판단에 쓰인다>
metadata:
  type: feedback | project | reference | user
---

<본문 = 교훈 한 문단.>

**Evidence:** <이 교훈의 근거가 된 **관찰한 사실** — 언제(절대 날짜) 어디서 무엇이 일어났나. "~할 것 같아서"는 근거가 아니다>
**Why:** <그 관찰을 이렇게 해석한 이유>
**How to apply:** <다음에 어떻게 행동하나>
<관련 메모리는 [[name]] 으로 잇는다.>
```

- **`MEMORY.md`가 색인이다.** 새 메모리를 만들면 한 줄(`- [제목](file.md) — 훅`)을 반드시 추가한다. 세션 시작 시 로드되는 건 색인뿐이고, 본문은 훅을 보고 필요할 때 꺼낸다. 색인에 없으면 파일이 있어도 죽은 메모리다.
- `feedback_`·`project_`는 **Evidence 가 없으면 쓰지 않는다.** 관찰 없이 넣은 메모리는 다음 세션부터 모든 Claude의 행동을 바꾸는데 되돌릴 근거도 없다(`doctor.py`가 없으면 WARN). 같은 cue 로 반대 관찰이 나오면 Evidence 를 갱신하거나 지운다.
- 같은 주제의 기존 항목을 먼저 찾는다. 있으면 **그 파일을 갱신**하고, 없을 때만 새 파일 + 색인 한 줄.
- 저장소가 이미 기록하는 것(코드 구조, git 이력, CLAUDE.md·BRAIN의 규칙)은 넣지 않는다. 그런 걸 기억하라고 하면 "비자명한 부분"만 추린다.
- 틀린 것으로 판명되면 지운다. 상대가 쓴 메모리를 고칠 땐 커밋 메시지에 왜 고쳤는지 남긴다.
- 어느 쪽 기기에서 썼든 형식은 같다. 메모리 본문에 **개인 절대경로**를 쓰지 않는다(상대에겐 없는 경로).

## 주의

메모리는 매 세션 무조건 로드되어 문서보다 강하게 행동을 좌우한다. **낡은 메모리는 낡은 문서보다 해롭다.** 경로·명령·파일명을 담았다면 쓰기 전에 아직 실재하는지 확인한다.
