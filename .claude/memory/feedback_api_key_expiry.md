외부 서비스 키(LLM·결제·지도 등)를 만들거나 교체하면 `docs/services.md`(외부 서비스 지도, 없으면 만든다)에 키 이름·비밀 값 위치·**`만료 YYYY-MM-DD`**·갱신 시점(만료 2주 전)·갱신 순서를 적는다. 표로 쓸 땐 머리줄에 `만료` 칸을 둔다. 세션 시작 상황판(`tools/harness/session_start.py`)이 만료 30일 안쪽이거나 지난 키를 ⚠로 띄운다. 교체가 끝난 옛 키 줄은 지우거나 만료일을 빼서 알림이 계속 뜨지 않게 한다. 키를 만들 때 만료를 고를 수 있으면 짧은 기본값(30일 등)을 그대로 두지 말고 사용자에게 기간을 묻는다.

**Evidence:** 2026-11-17 한 프로젝트에서 운영 서버의 LLM 키가 30일 만료로 만들어져 11-14에 끊겼고, 서버 오류 알림이 없어 사흘 동안 운영 대화가 전부 401(`invalid x-api-key`)이었는데 실기기 확인 때에야 발견했다.
**How to apply:** 키를 발급·교체할 때, 출시 전 점검 때. 실서비스 호출이 계속 실패하면 알리는 장치(서버 오류율 알림)는 프로젝트마다 따로 검토한다.
