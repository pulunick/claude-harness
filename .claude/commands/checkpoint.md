description: BRAIN.md(확정 사항)와 STATE.md(진행 상태)를 현재 세션 내용으로 갱신 — 세션 인수인계용
---

이번 세션에서 진행된 내용을 인수인계 문서에 반영하라:

1. `.claude/BRAIN.md`와 `.claude/STATE.md`를 읽는다.
2. 이번 세션에서 **사용자가 확정한 결정**(승인된 방향, 선택된 옵션, 채택된 도구/모델 등)을 BRAIN.md의 해당 장에 추가/갱신한다. 추측이나 미승인 제안은 넣지 않는다.
3. STATE.md를 갱신한다:
   - "다음 작업": 다음 세션이 바로 시작할 수 있게 구체적으로 (체크리스트 + 관련 파일 경로)
   - 완료된 항목은 목록에서 지우고 "완료 로그"에 날짜(여럿이 쓰는 저장소면 `[이름@기기]`도)와 함께 한 줄 요약. 로그가 15건을 넘으면 오래된 것부터 `docs/log/YYYY-MM.md`로 옮긴다(STATE는 "지금"만 담는다)
   - 새로 생긴 대기/보류 항목 추가
   - 두 세션 체제(`/role coding`·`review`)면 **상대 세션이 쓴 줄은 지우지 않는다** — 완료 항목을 로그로 옮기는 것도 자기 세션이 쓴 줄과 자기 요약 한 줄만. 상대 줄은 `[x]`·취소선으로 상태만 바꾼다. STATE를 재구성(정리·재배치)할 때도 상대 세션 줄은 정규식으로 골라 옮기지 말고 **원래 자리에 그대로 두거나, 통째로 `<details><summary>상대 세션 줄 (보존)</summary>` 블록에 넣는다** — 고친 뒤 상대 줄 수가 줄지 않았는지 diff로 확인
4. 두 파일의 "마지막 갱신" 날짜를 오늘로 바꾼다. 루트에 새 문서가 생겼다면 CLAUDE.md의 문서 위치 규칙대로 `docs/` 아래로 옮긴다.
5. 장기 기억에 저장할 가치가 있는 새 사실(작업 규칙·선호·프로젝트 방향 전환)이 있으면 메모리에 기록한다 — 저장소에 **공유 메모리 `.claude/memory/`**가 있으면 그 규약(`README.md`)대로 거기에(개인 사정은 `local_` 접두), 없으면 자동 메모리에. 프로젝트와 무관한 교훈(도구 함정, 작업 방식, 하네스 개선)은 **하네스 템플릿 되가져갈 후보**로 보고에 적는다.
6. 커밋은 `.claude/harness.json`의 `profile`로 가른다:
   - **solo**: 문서만 바로 커밋한다 — 경로를 지정해 `git add .claude/BRAIN.md .claude/STATE.md docs/log/*` + 이 세션이 고친 `docs/` 문서(코드 파일은 넣지 않는다). 프로젝트 CLAUDE.md에 **"체크포인트 커밋 대상"** 항목이 있으면, 거기 적힌 경로 안에서 이 세션이 만들거나 고친 파일도 넣는다(예: 공부 기록 프로젝트의 `<과목>/노트/`). 항목이 없는데 `docs/` 밖 산출물이 커밋에서 빠지게 되면, 임의로 넣지 말고 그 경로를 항목에 추가할지 사용자에게 묻는다. 메시지는 `체크포인트 YYYY-MM-DD: <한 줄>`. 경로 지정이라 다른 세션의 미커밋 코드와 섞이지 않는다. 커밋 뒤 **현재 브랜치를 push**한다(2026-11-02 사용자 결정):
     - 원격(`git remote`)이 없으면 건너뛰고 "원격 없음"만 보고한다.
     - 먼저 `git fetch`, 그리고 `git rev-list --count HEAD..@{u}`(upstream이 없으면 `HEAD..origin/<브랜치>`, 그것도 없으면 0)가 1 이상이면 **push하지 않고** "원격에 새 커밋 N개 — pull 후 다시"라고 보고만 한다. 자동 병합·rebase·`--force`는 하지 않는다.
     - push 전 범위를 기록해 둔다: `before=$(git rev-parse --short @{u} 2>/dev/null)`(없으면 "새 브랜치"). push는 단독 Bash로 `git push`(upstream 없으면 `git push -u origin <브랜치>`).
     - push 뒤 `git status -sb`로 원격과 같아졌는지 확인하고, 보고에 **올라간 범위 `<before>..<after>`와 커밋 수**를 적는다. 두 세션 체제면 상대 세션의 아직 승인 안 된 커밋도 함께 올라갈 수 있다 — 범위로 알 수 있게 하는 것이 목적이다. 상대 세션의 커밋이 함께 올라갔으면 그 세션에 SendMessage로 올라간 범위와 "따로 push할 필요 없음"을 알린다(상대 창에 push 여부를 묻는 질문이 떠 있을 수 있다).
     - 네트워크·인증 실패면 체크포인트(커밋)는 완료로 두고, 실패 사실과 에러 한 줄만 보고한다. 재시도·다른 방법 우회는 하지 않는다.
   - **team**(또는 harness.json 없음): 커밋·푸시는 하지 않는다 — 그건 `/wrap`의 몫이다
7. 마지막에 변경 요약을 사용자에게 보고한다. $ARGUMENTS
